3. DATABASE ARCHITECTURE
------------------------
Q: Your current system uses in-memory storage + JSON file persistence, correct?
A: Yes. It uses a high-speed in-memory JavaScript array (historyCache) for O(1) 
   state updates, backed by an asynchronous JSON file (backend/data/location_history.json) 
   to persist state across server restarts.

Q: Why didn't you use MySQL or MongoDB?
A: (Strong, professional answer for examiners):
   1. Ultra-Low Latency & High Frequency: Location updates arrive every 1-2 seconds. 
      Performing database roundtrips, connection pooling, and disk writes on every 
      packet introduces unnecessary latency. RAM operations execute in sub-milliseconds.
   2. Ephemeral Data Lifecycle: GPS telemetry in this system is transient; coordinates 
      are designed to expire after 24 hours. A heavyweight relational schema with 
      ACID transaction overhead is unnecessary for temporary tracking records.
   3. Zero Database Daemon Dependency: Using an in-memory cache with JSON disk sync 
      eliminates the need to install and configure heavy database services 
      (mongod or mysqld), making the project completely portable.
   4. Storage Efficiency: Thanks to our in-place deduplication (`name___semester`), 
      80 active students consume less than 150 KB of disk space in JSON format.


4. AUTHENTICATION MECHANISM
---------------------------
Q: Is the admin authentication currently just the hardcoded admin/admin123 login?
A: Yes, for the current demonstration prototype, credentials are validated against 
   admin / admin123 on the client form.

Q: Is there JWT or session authentication?
A: It uses browser sessionStorage:
   - Upon successful credential match, sessionStorage.setItem('adminAuth', 'true') is set.
   - React Router enforces this via a <ProtectedRoute> component that checks 
     sessionStorage.getItem('adminAuth') === 'true' and redirects unauthorized 
     attempts to /admin-login.
   - For an enterprise institutional production release, migrating to backend-issued 
     JWTs (JSON Web Tokens) stored in httpOnly, Secure cookies with bcrypt password 
     hashing would be the next step.


5. DEPLOYMENT SETUP
-------------------
Q: Are you presenting it as a local/demo system, or is it deployed online?
A: It is presented as a Local / Demonstration System with remote cellular access:
   - Local Setup: The Node.js server and Vite React app run locally on the host laptop.
   - Mobile Access over Wi-Fi: Mobile phones connect to the host's private Wi-Fi IP 
     over HTTPS (e.g., https://192.168.1.15:5173/tracker) via @vitejs/plugin-basic-ssl.
   - Mobile Access over Cellular (4G/5G): When testing on mobile data, we run 
     `npm run tunnel` (which establishes an SSH reverse tunnel via localhost.run), 
     providing a secure public HTTPS URL (e.g., https://xxxx.lhr.life/tracker).
   - Why not deployed on cloud platforms (e.g., Vercel / Render)?
     Free cloud tiers often terminate persistent WebSocket connections, introduce 
     cold-start sleep delays (15–30 seconds), and complicate local network hardware 
     testing. Running the server locally provides guaranteed sub-60ms responsiveness.


6. LIVE DEMONSTRATION PLAN & POTENTIAL ISSUES
---------------------------------------------
Q: Are you going to actually demonstrate a phone sending its location -> admin map 
   showing the student?
A: Yes, that is the core live demonstration planned for the panel:
   1. Laptop displays the Admin Dashboard (https://localhost:5173/admin).
   2. A physical mobile smartphone opens https://<IP>:5173/tracker.
   3. The student enters their name, selects a semester, checks "Bypass Time Restriction" 
      (if presenting off-hours), and taps "Share My Location".
   4. The panel sees a live blue/green marker appear on the laptop's OpenStreetMap 
      within 100 milliseconds, and a new record appears in the 24h History Table.

Potential Demo Issues & Fast Solutions:
1. Issue: Mobile browser shows "Your connection is not private" (SSL Warning).
   Solution: Expected behavior with self-signed dev certificates. Tap "Advanced" -> 
   "Proceed to IP (unsafe)".
2. Issue: Phone shows "Outside of college hours (9:00 AM to 4:15 PM IST)".
   Solution: Check the "Bypass Time Restriction" checkbox before clicking "Share My Location".
3. Issue: Mobile phone location is not showing up on map.
   Solution: Ensure the mobile phone and laptop are connected to the exact same Wi-Fi 
   network, or use the `npm run tunnel` public link.
4. Issue: Browser asks "Allow location access?" and student accidentally hits Block.
   Solution: Go to browser site settings, click "Reset Permissions", and refresh the page.
